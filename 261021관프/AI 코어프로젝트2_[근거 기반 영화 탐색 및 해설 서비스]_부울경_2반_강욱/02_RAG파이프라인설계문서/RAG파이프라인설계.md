# RAG 파이프라인 설계문서

## 1. 두 Vector DB 컬렉션 구조와 메타데이터 필드

동일한 Chroma 저장소 안에 영화 메타데이터와 외부 문서용 컬렉션을 분리한다. 항목 정보 1건은 반드시 포함하고 긴 배경 문서는 질문에 맞는 청크만 검색하기 위한 선택이다. 임베딩 모델·API 주소의 해시를 컬렉션명에 붙여 서로 다른 벡터 공간이 섞이지 않게 한다.

| 구분 | 영화 메타데이터 | 외부 문서 |
|---|---|---|
| 컬렉션명 | movie_meta_<설정해시> | movie_wiki_<설정해시> |
| 저장 단위 | 영화 1편의 속성을 합친 텍스트 1건 | 위키/PDF 본문 청크 |
| ID | movie_id | movie_id:page_id:chunk_index |
| 공통 필드 | movie_id, title, url, source, source_type, source_kind | movie_id, title, url, source, source_type, source_kind |
| 추가 필드 | content_hash | page_id, related_movie, search_query, collected_at, chunk_index, index_signature, page, file_id, license, license_url |

감독·장르·연도·상영시간 등 영화 속성은 메타데이터 **본문**에 포함한다. 별도 메타데이터 필드로 저장된 것으로 혼동하지 않는다. PDF는 page/file_id를 기록하고 위키는 기본 page=0, file_id=빈 문자열을 사용한다. 두 컬렉션 모두 실제 임베딩 벡터와 문서 본문을 보관한다.

## 2. 문서 수집·청킹·색인 흐름

1. movies.json을 읽어 영화당 하나의 속성 텍스트를 만든다.
2. 영화 텍스트를 임베딩하고 movie_id로 메타 컬렉션에 upsert한다. content_hash가 같은 항목은 생략한다.
3. 영화·질문·최근 대화를 검색어 추출 프롬프트에 전달한다. 영화 자체 검색어는 별도로 항상 추가한다.
4. 영화/검색어의 완료 캐시가 있으면 외부 검색과 선별을 생략하고 저장 원문을 재사용한다.
5. 위키 검색 결과 또는 배포 묶음에서 최대 5개의 제목·요약 후보를 구성한다.
6. 후보 선별 프롬프트로 최대 3개 page_id를 선택한다. 영화 자체 문서는 선별 결과와 관계없이 포함한다.
7. 선택한 본문·URL·출처를 저장한다. 자체 문서 미확보나 빈 본문은 성공으로 기록하지 않는다.
8. 본문을 기본 1,000자·중복 200자로 분할한다. PDF는 등록된 연결 영화의 2~4쪽을 각각 추출하고 쪽 경계를 넘지 않는다.
9. 청크를 임베딩해 외부 컬렉션에 저장한다. 설정/본문이 같으면 생략하고 재청킹하면 남은 이전 청크 ID를 삭제한다.
10. 색인까지 성공한 검색어만 완료 캐시에 기록한다.

## 3. 검색 결과 병합과 중복 제거

LangGraph는 retrieve와 generate 두 노드로 구성한다. 수집·색인은 그래프 진입 전에 수행한다.

```mermaid
flowchart LR
  A[영화와 질문] --> B[검색어 추출·후보 선별·수집]
  B --> C[청킹·임베딩·색인]
  C --> D[retrieve]
  D --> E[generate]
  E --> F[답변과 인용 근거]
```

retrieve는 선택 영화의 메타데이터 1건을 ID로 가져와 고정한다. 외부 검색에는 같은 movie_id 필터를 적용하고 문서 유형별 의미 검색 후보를 모은다. 동일 본문 해시의 후보를 제거한 뒤 유사도 또는 MMR로 선택한다. 슬롯이 충분하면 유형별 최상위 후보를 최소 한 개 보존한다.

메타데이터와 선택 외부 청크를 병합하고 ID와 본문 SHA256으로 다시 중복을 제거한다. 최종 목록은 Top-k를 넘지 않는다. 기본 6건은 메타데이터 1건과 외부 최대 5건이며, 중복 제거 후에는 더 적을 수 있다.

## 4. 세 프롬프트의 역할과 출력 형식

| 프롬프트 | 역할·입력 | 출력 형식·제약 | 선택 이유 |
|---|---|---|---|
| 검색어 추출 | 영화 큐레이터가 영화·질문·최근 대화에서 검색어 추출 | 최대 3개의 짧은 문자열 JSON 배열. 영화 자체 검색어는 코드에서 추가 | 긴 질문을 검색 가능한 단어로 바꾸되 구조화 출력으로 파싱 가능하게 함 |
| 후보 선별 | 영화 조사 담당자가 후보 제목·요약과 질문의 관련성 판단 | 최대 3개 page_id 문자열 JSON 배열 | 관련 없는 본문 수집과 임베딩을 줄이기 위해 본문 수집 전에 선별 |
| 답변 생성 | 번호를 붙인 원문 근거·질문·최근 대화로 답변 | 한국어 텍스트, 주요 주장마다 [근거 N], 자료가 부족하면 확인 불가 | 영화 사실과 배경 해설을 추적 가능한 원문에 연결 |

JSON은 엄격하게 파싱하고 형식이 맞지 않으면 제한 횟수 내 재요청한다. 문서·질문·대화 안의 지시 무시/비밀 공개 명령은 따르지 않도록 제한한다. 이전 대화는 지시 대상 해석에만 쓰고 사실 근거로 사용하지 않는다. 숫자·단위·수량 범위는 원문과 대조하며 불확실한 번역은 원문 표현을 유지한다.

## 5. 청크 크기·중복 길이·Top-k 선택 이유와 변경 차이

| 설정 | 기본값과 이유 | 줄일 때 | 늘릴 때 |
|---|---|---|---|
| 청크 크기 | 1,000자: 문맥과 모델 입력량의 균형 | 청크 수 증가, 세부 검색 가능, 문맥 분절 가능 | 청크 수 감소, 문맥 보존, 무관 문장 혼입 가능 |
| 중복 길이 | 200자: 분할 경계의 정보 단절 완화 | 저장량 감소, 경계 연결 약화 가능 | 경계 보존 증가, 저장량·중복 증가 |
| Top-k | 총 6건: 메타 1건 + 외부 최대 5건 | 입력량 감소, 필요한 근거 누락 가능 | 근거 폭 증가, 지연·입력량·무관 자료 증가 가능 |

표의 차이는 설계상 예상이다. 실제 기본값의 답변과 지연을 측정했고, 재청킹·Top-k 상한은 자동 검사했다. 모든 설정별 실제 정답률을 측정한 것은 아니다. MMR은 기본 λ=0.5로 질문 관련성과 근거 다양성을 함께 고려한다.

## 6. 답변에 근거를 표시하는 방식

검색 목록을 1부터 번호 매겨 유형·제목·본문과 함께 생성 모델에 제공한다. 모델은 주요 주장 뒤에 [근거 N]을 붙인다. 생성 후 범위를 벗어난 번호나 인용 누락을 검사한다. 확인 불가 응답은 인용이 없어도 허용한다.

화면은 답변에서 실제 인용된 번호만 골라 제목·본문 일부·원문 URL·출처 유형을 표시한다. PDF는 쪽 번호와 #page=N 링크를 보존한다. 인용이 없으면 그 사실을 안내한다. 유효한 번호가 사실성을 자동 보증하는 것은 아니므로 검증 단계에서 원문과 내용을 대조한다.

## 7. 도메인 특화 기능의 설계 이유

관람 가이드는 작품 소개와 과학·역사 배경을 연결하는 영화 해설 목적에 맞춰 선택했다. 작품 소개·관람 전 배경·확인되지 않는 사항을 같은 근거 정책으로 생성한다.

조건 탐색은 연도·상영시간·언어·장르 등 명시 조건을 먼저 검사한 후 의미 검색 후보를 모델로 검증한다. 추천 문구만으로 조건이 어긋나는 영화를 반환하는 일을 줄이기 위해서다. 지원하지 않는 OR·부정·실시간 OTT 조건은 안내한다.

## 8. 선택 이유와 겪은 문제·해결 과정

| 대상 | 문제 또는 설계 판단 | 선택 및 해결 |
|---|---|---|
| 컬렉션 분리 | 긴 배경 문서에 영화 자체 정보가 밀릴 수 있음 | 메타와 외부를 분리하고 선택 영화 메타 1건 고정 |
| 문서 ID | 같은 위키 문서를 여러 영화가 공유하면 덮어쓸 수 있음 | movie_id:page_id:순번으로 식별 |
| 청킹 갱신 | 청크 크기를 키우면 기존 뒤쪽 청크가 잔존할 수 있음 | 새 청크 저장 후 남은 이전 ID 삭제 |
| 검색 유형 | 한국어 위키가 영어 PDF를 밀어 질량 범주 근거가 기존 순위 56위에 위치 | 유형별 후보를 확보하고 슬롯이 충분하면 유형별 근거 보존 |
| 생성 프롬프트 | 수량어 hundreds of thousands를 잘못 번역한 중간 응답 | 숫자·단위·범위를 원문과 대조하고 불확실한 수량은 원문 유지하도록 보완 |
| 배포 문서 대응 | 묶음 모드 13편은 자체 영화 문서를 식별하지 못함 | 잘못된 작품을 대신 쓰지 않고 중단 안내. 올바른 문서 대응 확보는 미해결 |

유형별 근거 확보와 프롬프트 보완 후 최종 대표 답변에서 PDF 인용과 수십만~수십억 범위를 확인했다. 향후 모든 응답의 정확성을 보장하는 것으로 해석하지 않는다.
