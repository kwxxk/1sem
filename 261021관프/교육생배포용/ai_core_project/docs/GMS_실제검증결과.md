2026-10-21 / 대상: `교육생배포용/ai_core_project`

## 원문 대조 결과 (Codex 검토)

사람의 셀프·상호 평가를 대신한 것으로 표시하지 않는다. 비교 JSON의 `human_review_complete`는 false로 유지했다.

| 질문 | 최종 RAG 응답과 원문 대조 |
|---|---|
| 상영 시간·감독 | 배포 메타데이터의 169분, 크리스토퍼 놀란과 일치. 근거 1 인용 |
| 제작 국가·연도 | United Kingdom, United States of America / 2014와 일치. 근거 1 인용 |
| 사건의 지평선 | 위키 원문에서 안쪽으로 들어간 빛은 탈출 불가라는 설명과 일치 |
| 두 질량 범주 | NASA PDF 2쪽의 항성질량 5배~수십 배, 초대질량 수십만 배~수십억 배와 최종 응답 일치. PDF 근거 6 인용 |
| 우주복 일련번호 | 검색된 원문에 번호가 없어 확인 불가로 답함. 전체 웹/영상에 없다는 주장으로 확대하지 않음 |

RAG 미사용 응답도 기본 영화 정보와 확인 불가 질문에는 올바르게 답했다. 이 5개 사례만으로 RAG가 모든 질문에서 더 정확하다고 결론 내리지 않는다. RAG는 응답이 실제로 참조한 문서를 제시하므로 사실 대조가 가능하다.

## 검증 중 발견한 문제와 수정

1. 한국어 질문에 대해 긴 한국어 위키 문서가 영어 NASA PDF를 검색 상위에서 밀어냈다. 질량 범주 질문의 PDF 최상위 청크는 기존 전체 순위 56위였다. `Store.retrieve`가 영화별 범위를 유지한 채 문서 유형별로 의미 검색 후보를 확보하도록 수정했다. 슬롯이 충분하면 각 유형의 최상위 후보를 최소 한 개 유지한다. 메타데이터 고정 포함, 중복 제거, Top-k 제한과 MMR은 유지한다. 유형 대표 문서가 포함되는 것이 질문 관련성이나 사실 정확성을 보장하지 않으므로 생성 단계는 여전히 원문에 없는 내용은 거부한다.

2. 중간 재검증에서 모델이 원문의 “hundreds of thousands”를 “100만”으로 잘못 옮긴 응답이 한 차례 나왔다. 수량·단위·범위를 원문과 대조하고 대략적 수량을 임의의 단일 숫자로 바꾸지 않도록 프롬프트를 보완했다. 최종 비교 응답과 반복 응답에서는 “수십만~수십억”으로 확인했다. 프롬프트 보완이 모든 향후 응답의 수치 정확성을 보장하지는 않는다. 중간 실행 기록도 `.local/evaluations/`에 남겼다.

3. 유형 혼합 검색에서도 다른 영화 문서를 섞지 않고 최대 근거 수를 지키는 회귀 검사를 추가했다.

## 실제 처리 시간

단위: 초. 최초 실행은 질문별 새 검색어 수집을 포함하고, 메타데이터 전체 임베딩 시간은 제외한다. 같은 영화/검색어가 다른 질문에서 재사용되므로 완전히 초기화한 시스템의 cold start 측정은 아니다. 최종 재검증과 반복 요청은 문서 수집 캐시가 있는 상태다.

| 질문 | 최초 실행 | 수정 후 재검증 (문서 캐시 있음) | 최종 반복 |
|---|---:|---:|---:|
| 상영 시간·감독 | 7.443 | 1.517 | 0.963 |
| 제작 국가·연도 | 4.430 | 1.137 | 0.986 |
| 사건의 지평선·빛의 탈출 | 6.879 | 1.817 | 1.875 |
| 블랙홀 질량 범주·범위 | 6.214 | 2.578 | 1.686 |
| 확인 불가 일련번호 | 3.064 | 1.204 | 1.221 |

최종 반복 5건 모두 수집 캐시를 재사용했다. 최초 요청 120초·반복 요청 30초라는 프로젝트 내부 목표 안에 들어왔다. 이는 단일 로컬 환경의 표본이며 동시 사용자 부하/최악 지연 보장은 아니다.

## 키와 Git 제외 확인

- Git `check-ignore`로 `.env`, `.env.local`, `.venv/`, `venv/`, `.local/` 제외를 확인했다. `.env.example`은 추적 가능하다. 실제 프로젝트는 아직 Git 저장소로 초기화되어 있지 않아 같은 .gitignore를 복사한 임시 저장소에서 검증했다.

- 소스·문서·JSON 로그 등 70개 텍스트 파일을 확인했으며 `.env` 밖에 제공받은 키와 일치하는 값은 없었다. 가상환경·바이너리·캐시 전체에 대한 포렌식 검사는 아니다.

- 실제 서버에서 `/.env`는 404이고, 키는 브라우저 API/화면/캡처로 전달하지 않는다.

## 남은 제약

- 이번 실제 외부 자료 검증의 대표 영화는 인터스텔라다. 영화 964개 전체의 외부 문서와 답변 품질을 검증한 것은 아니다.

- WIKI_CONTACT가 없어 배포 위키 묶음을 사용했다. Wikimedia 실시간 API의 현재 연결/호출 제한 동작은 실제로 검증하지 않았다. 재시도·간격 처리는 모의 응답 테스트로 확인했다.

- 기존에 확인한 묶음 모드 13편의 자체 영화 문서 식별 제약은 남아 있다. 해당 작품은 자료 대응을 보완해야 한다.

- 실제 셀프·상호 체크리스트와 사람의 5개 응답 검토/서명은 사용자가 작성해야 한다.

## 실행

이 프로젝트 폴더에서 Git Bash 기준 `./.venv/Scripts/python.exe serve.py`를 실행한 뒤 http://127.0.0.1:8000 을 연다. 기존 서버가 실행 중이었다면 키와 코드 적용을 위해 재시작한다. Streamlit은 `./.venv/Scripts/python.exe -m streamlit run app.py`로 실행한다.
