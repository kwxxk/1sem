# 심화 및 비기능 구현·검증

2026-10-21. 대상: ai_core_project. 기존 필수 Streamlit 실행 경로와 두 노드 RAG를 유지하고 심화 UI/API를 추가했다.
아래의 자동·브라우저 결과는 **실제 GMS 답변 품질 검증과 구분**한다. GMS 키는 아직 사용하지 않았다.

MMR은 메타데이터 1건을 고정하고 외부 후보 30건 중 Top-k-1건을 선택한다. λ=0.5를 기본으로
질문 관련성과 이미 고른 근거와의 차이를 같은 비중으로 고려한다. 후보가 적으면 결과가 같을 수 있고,
이를 억지로 다르게 만들지 않는다. 필수 검색과 심화 검색은 같은 색인·질문·Top-k로 비교한다.

## API·세션

서버는 기본 127.0.0.1에만 바인딩한다. HTML/CSS/JS는 /assets, 데이터는 /api로 분리한다.
HttpOnly·SameSite 세션 쿠키로 대화와 작업 결과를 구분하고 다른 세션의 작업을 조회할 수 없게 했다.
동시 작업자 2개, 대기 포함 최대 8개, 최근 작업 128개, 세션 128개/1시간으로 제한한다.
다른 Origin의 변경 요청과 알 수 없는 Host를 거부한다. API는 키·파일 경로·서버 traceback을 반환하지 않는다.

서비스 실행을 위한 로그인이나 외부 공개 배포 기능을 추가한 것은 아니다. 채팅은 현재 서버 세션에 유지되며,
서버 재시작 후 비교 JSON은 .local/evaluations에 남지만 웹의 세션 소유권은 초기화된다. CLI로 보고서를 내보낼 수 있다.

## 검증 결과

- Python 자동 테스트: 기존 필수 14개 + 심화/비기능 12개 = **26개 통과**.
- 실제 Edge 브라우저: 질문·안전한 텍스트·영화별 대화·MMR 비교·5쌍 수집·평가 저장·PDF·모바일 흐름 통과.
- JavaScript 구문 검사 및 pip check 통과.
- Windows의 .js MIME이 text/plain인 환경에서 모듈 로딩 실패를 발견해 text/javascript 응답으로 수정하고 회귀 검사 추가.
- screenshots/의 test 이미지에는 “테스트 모델 · 실제 GMS 미사용” 표시가 있다. 이 캡처를 실제 모델 품질 증빙으로 제출하면 안 된다.
- 실제 키 없는 제품 화면도 별도로 캡처한다. 실제 답변·성능·셀프/상호 평가 결과는 아직 없다.

## 남은 사항

1. 키 설정 후 실제 메타데이터 색인, 질문, MMR 비교, PDF 검색 수행.
2. “5개 질문의 실제 답변 비교 실행” 후 원문을 보고 평가와 이유를 저장하고 보고서 내려받기.
3. 대표 질문의 실제 첫/반복 시간을 측정하고 내부 목표가 적절한지 확인.
4. 기존 점검에서 확인된 묶음 모드 13편의 자체 영화 문서 식별 제약은 그대로 남아 있다. 해당 영화의 올바른 문서/작품 대응을 확보해야 한다.
5. 실제 GMS 화면 캡처와 셀프·상호 체크리스트 작성. 이번 구현으로 실제 검증이 끝난 것으로 표시하지 않는다.

이전 요구사항_체크리스트_점검결과.md는 심화 구현 전의 사전 점검 이력이다.
심화를 모두 선택했으므로 그 문서의 15~19번 “해당없음”은 현재 상태에 적용하지 않는다.
현재는 구현·로컬 검증 완료 / 실제 비교 결과·품질 검증 대기로 구분한다.
