# PDF 프로젝트 구조 반영

기준: 요구사항 PDF 5쪽의 5개 영역 및 10쪽 NF2005.

| 요구 영역 | 실제 파일 | 책임 |
|---|---|---|
| 데이터 준비 | preparation/movies.py | 영화 로드·텍스트 구성·동일 작품 판별 |
| 데이터 준비 | preparation/documents.py | 위키 API·배포 문서 검색·선별·수집·원문 저장 |
| 데이터 준비 | preparation/domain.py, prompts.py, movie_filters.py | 영화 필드·컬렉션·프롬프트·조건 규칙 |
| Vector Store | store.py | 도메인 어댑터로 받은 레코드의 청킹·임베딩·색인·검색 |
| RAG 파이프라인 | pipeline.py, citations.py | retrieve/generate, 근거 번호 부여·검사 |
| 서비스 기능 | service.py, explore.py | 질문·관람 가이드·조건 기반 탐색 실행 |
| UI | app.py | 항목 선택·입력·채팅·근거·진행·오류 표시 |

공통 Store와 LangGraph에는 영화 ID 필드명, TMDB 속성, 영화별 별칭,
영화 역할 프롬프트를 직접 넣지 않는다. 데이터 준비 영역의 MovieDomain을
Service에서 조립해 전달한다. 위키백과에 종속된 수집 코드는 데이터 준비 영역에 둔다.

관람 가이드 요청과 생성 지침도 데이터 준비 영역에 있다. UI 버튼은 `Service.guide()`를
호출하고, 이 메서드가 동일한 근거 수집·검색·생성 파이프라인을 실행한다.
조건 탐색 UI는 `Service.find_items()`를 호출한다.

테스트에서 별도의 도서용 어댑터를 주입해 Store·LangGraph가 영화 필드 없이 동작하는지
확인한다. 이는 분리 검증용이며 제품의 도메인을 추가한 기능은 아니다.

## 심화 확장

web/: HTML/CSS/JS 프론트엔드. movielab/webapi/: 세션·작업·요청/응답·정적 파일 API.
preparation/pdf_documents.py: 등록 PDF 수집·쪽별 텍스트·출처.
retrieval.py: 도메인 독립 MMR. evaluation.py: 비교·원문 대조 평가·보고서·성능 측정.
operations.py: 호출 간격·안전한 오류·제한 캐시·성능 로그.
새 실행 진입점은 serve.py이며 기존 app.py는 필수 Streamlit 경로로 유지한다.
